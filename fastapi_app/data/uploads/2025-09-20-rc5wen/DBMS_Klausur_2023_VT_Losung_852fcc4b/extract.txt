n) Stellen Sie sicher, dass in der Couple-Tabelle jeder Character maximal 3x vorhanden ist. (6 Punkte) 
CREATE FUNCTION checkCouple() RETURNS TRIGGER AS 
$$ 
BEGIN 
 IF EXISTS 
 (SELECT COUNT(femID) FROM Couple GROUP BY femID HAVING COUNT(femID) > 3) 
 UNION 
 (SELECT COUNT(malID) FROM Couple GROUP BY malID HAVING COUNT(malID) > 3) 
 THEN RAISE EXCEPTION 'Jeder Character darf nur maximal 3x verheiratet (gewesen) sein.'; 
 END IF; 
RETURN NULL; 
END; 
$$ LANGUAGE plpgsql; 
 
CREATE TRIGGER checkCouple 
AFTER INSERT OR UPDATE ON Couple 
FOR EACH ROW 
EXECUTE FUNCTION checkCouple();

e) Welche Probleme existieren beim Einfügen in Tabellen, die sich gegenseitig durch 
 Fremdschlüssel referenzieren? Wie kann das Problem gelöst werden? (2.5 Punkte) 
Bei zwei Tabellen die sich gegenseitig durch Fremdschlüssel referenzieren können keine Datensätze 
hinzugefügt werden, da sonst immer ein Fremdschlüsselconstraint verletzt werden würde. Umgehen 
kann man dieses Problem, indem man die Überprüfung des Constrai nts temporär ans Ende einer 
Transaktion verschiebt und zwischenzeitlich die neuen Datensätze hinzufügt. 
f) Welche drei Möglichkeiten existieren, um in SQL die referenzielle Integrität (m.H. der Definition 
 von Foreign Keys) beim Update oder Delete sicherzustellen? Nennen Sie die drei Möglichkeiten 
 und erläutern Sie diese kurz (ein Satz). (3 Punkte) 
Mögliche Reaktionen in einer Fremdschlüsseltabelle: 
1. CASCADE: Beim Update / Delete soll sich sie Aktion fortpflanzen 
2. RESTRICT: Beim Update / Delete soll die Aktion abgelehnt werden 
3. SET DEFAULT bzw. SET NULL: Beim Delete soll der Standardwert bzw. NULL eingefügt werden

 SELECT * FROM X NATURAL JOIN Y WHERE COUNT(a) > 10; 
Die Anfrage ist syntaktisch fehlerhaft, da einerseits eine Aggregatfunktion in der WHERE-Klausel statt 
in der HAVING-Klausel verwendet wird, und andererseits, weil man im SELECT die Attribute a und b 
ausgeben möchte während man eine Aggregatfunktion verwendet, ohne auf sie gruppiert zu haben.
