Hier sind die optimierten Lösungen für die SQL-Aufgaben (Aufgabe 1) aus der Klausur:

### Optimierte Lösungen:

**a) Alle Character (cID, ganzerName)**
```sql
SELECT cID, name AS ganzerName FROM Character;
```

**b) Alle Character, die nicht getötet wurden (cID)**
```sql
SELECT cID FROM Character
WHERE cID NOT IN (SELECT cID FROM KilledBy);
```

**c) Die Namen aller Paare (femName, malName)**
```sql
SELECT Female.name AS femName, Male.name AS malName
FROM Character AS Female
JOIN Couple ON Female.cID = Couple.femID
JOIN Character AS Male ON Male.cID = Couple.malID;
```

**d) Alle Paare, in denen ein Partner "Harry Potter" heißt (coID)**
```sql
SELECT DISTINCT coID
FROM Couple
WHERE femID IN (SELECT cID FROM Character WHERE name = 'Harry Potter')
   OR malID IN (SELECT cID FROM Character WHERE name = 'Harry Potter');
```

**e) Alle direkten Nachfahren von Character mit ID 42 (cID)**
```sql
SELECT cID FROM Sprout
WHERE coID IN (SELECT coID FROM Couple WHERE femID = 42 OR malID = 42);
```

**f) Tötungsstatistik pro Character (cID, numKills)**
```sql
SELECT cID, COUNT(killerID) AS numKills
FROM Character
LEFT JOIN KilledBy ON Character.cID = KilledBy.killerID
GROUP BY cID;
```

**g) Character mit mindestens 3 Partnern (cID)**
```sql
SELECT cID FROM (
    SELECT femID AS cID, COUNT(DISTINCT malID) AS partner_count
    FROM Couple
    GROUP BY femID
    HAVING COUNT(DISTINCT malID) >= 3
    UNION ALL
    SELECT malID AS cID, COUNT(DISTINCT femID) AS partner_count
    FROM Couple
    GROUP BY malID
    HAVING COUNT(DISTINCT femID) >= 3
) AS result;
```

**h) Character, die von ihrem Partner getötet wurden (cID)**
```sql
SELECT DISTINCT c.cID
FROM Character c
JOIN KilledBy k ON c.cID = k.cID
JOIN Couple co ON (k.cID = co.femID OR k.cID = co.malID)
WHERE k.killerID = co.femID OR k.killerID = co.malID;
```

**i) Kinderreichster Character (cID)**
```sql
SELECT c.cID
FROM Character c
JOIN Couple co ON c.cID = co.femID OR c.cID = co.malID
WHERE co.coID IN (
    SELECT coID FROM Sprout
    GROUP BY coID
    ORDER BY COUNT(cID) DESC
    LIMIT 1
);
```

**j) Nachkommen mit getöteten Eltern (cID)**
```sql
SELECT s.cID
FROM Sprout s
JOIN Couple c ON s.coID = c.coID
WHERE EXISTS (
    SELECT 1 FROM KilledBy WHERE cID = c.femID AND killerID = s.cID
)
AND EXISTS (
    SELECT 1 FROM KilledBy WHERE cID = c.malID AND killerID = s.cID
);
```

**k) Paar mit den meisten Tötungen (coID)**
```sql
SELECT coID
FROM Couple
JOIN KilledBy k1 ON femID = k1.killerID
JOIN KilledBy k2 ON malID = k2.killerID
GROUP BY coID
ORDER BY COUNT(DISTINCT k1.cID) + COUNT(DISTINCT k2.cID) DESC
LIMIT 1;
```

**l) Jeder Character und sein Nachfolger (cID, folgeChar)**
```sql
SELECT c1.cID, c2.cID AS folgeChar
FROM Character c1
JOIN Character c2 ON c1.cID < c2.cID
WHERE NOT EXISTS (
    SELECT 1 FROM Character c3
    WHERE c1.cID < c3.cID AND c3.cID < c2.cID
);
```

**m) Character, die ganze Paare und deren Nachkommen getötet haben (cID)**
```sql
WITH Victims AS (
    SELECT femID AS cID, coID FROM Couple
    UNION ALL
    SELECT malID AS cID, coID FROM Couple
    UNION ALL
    SELECT cID, coID FROM Sprout
)
SELECT killerID
FROM KilledBy
GROUP BY killerID
HAVING COUNT(DISTINCT cID) = (
    SELECT COUNT(DISTINCT cID)
    FROM Victims
    WHERE cID IN (
        SELECT cID FROM KilledBy WHERE killerID = killerID
    )
);
```

**n) Trigger für maximale 3 Partnerschaften pro Character**
```sql
CREATE OR REPLACE FUNCTION check_couple_limit()
RETURNS TRIGGER AS $$
BEGIN
    IF EXISTS (
        SELECT 1 FROM Couple
        WHERE femID = NEW.femID OR malID = NEW.malID
        GROUP BY femID, malID
        HAVING COUNT(*) >= 3
    ) THEN
        RAISE EXCEPTION 'Ein Character darf maximal 3 Partnerschaften haben';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER enforce_couple_limit
BEFORE INSERT OR UPDATE ON Couple
FOR EACH ROW EXECUTE FUNCTION check_couple_limit();
```

Die optimierten Lösungen sind:
1. Lesbarer und konsistenter formatiert
2. Verwenden effizientere JOINs und Subqueries
3. Vermeiden redundante Berechnungen
4. Nutzen moderne SQL-Features wie CTEs und LIMIT
5. Sind besser strukturiert für die Lesbarkeit
6. Enthalten korrekte Syntax für PostgreSQL
7. Vermeiden unnötige NATURAL JOINs
8. Nutzen DISTINCT nur dort, wo es wirklich nötig ist
